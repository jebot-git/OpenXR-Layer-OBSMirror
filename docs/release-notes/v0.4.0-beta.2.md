# v0.4.0-beta.2 — OBS 30 Windows compatibility

Fixes the Windows capture sources failing to appear in OBS 30.2.3. Beta.1 used
OBS 32 headers, which passed a 424-byte source registration structure to an
OBS 30 runtime that accepts 408 bytes. The DLL loaded but neither source was
registered, leaving the OpenXR layer waiting for a consumer heartbeat.

- Build the Windows plugin with OBS 30.2.3 headers and libraries.
- Test the packaged DLL against OBS 30.2.3 and 32.2.2, including registration,
  translated source names, properties, and source creation/destruction.
- Log the OBS runtime, build API, and registration size for diagnosis.
- Rebuild Windows installer/portable and Linux packages. Vulkan capture behavior
  is unchanged from beta.1.

Close OBS and the VR application, install this update, then add **VR Mirror
Capture (Auto: OpenXR / SteamVR)** to your scene. An existing **OpenVR Capture**
source from the separate `win-openvr` plugin does not capture VirtualDesktopXR.
Install the complete package so the locale, presets, and companion DLL are
present. If you manually copied beta.1 into OBS's application directory, replace
that copy too or remove it before using the installer to avoid duplicate plugins.

Automated tests cover module compatibility and Vulkan transfers, not a live
headset session. Vulkan still uses host readback. Linux remains experimental
and native-only; see `docs/LINUX.md` and `docs/VULKAN.md`. Windows binaries are
unsigned.
